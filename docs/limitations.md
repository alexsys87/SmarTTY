# Ограничения текущей реализации

- **X11 forwarding:** запрашивается только для каналов с PTY — обычных вкладок, команд Smart Terminal и `sudo` в редакторе; служебные команды без PTY `DISPLAY` не получают. Локальный X-сервер всегда ищется на `localhost:6000` (дисплей `:0`, как у VcXsrv по умолчанию). SmarTTY проверяет случайный cookie `MIT-MAGIC-COOKIE-1`, выданный серверу, и передаёт соединение X-серверу без авторизационных данных: VcXsrv пускает локальные соединения по адресу, своего файла Xauthority для X-сервера SmarTTY не использует. Другие протоколы авторизации X11 и режим доверенной пересылки (`ssh -Y`) отдельно не реализованы. VcXsrv не входит в репозиторий: его нужно установить (SmarTTY предлагает скачать установщик последнего выпуска с GitHub — только 64-битный, установка требует прав администратора) или указать свой X-сервер. Пересылка реализована своими каналами на открытых событиях сессии SSH.NET; для отправки сообщений канала и выделения номера канала используются два внутренних члена SSH.NET через reflection — они проверяются тестами `tests/SshNetIntegrationTests` при обновлении библиотеки. На OpenWrt (Dropbear) X11 forwarding обычно недоступен.
- **Telnet:** реализованы базовые опции, LINEMODE, NEW-ENVIRON, TSPEED, XDISPLOC, STATUS (с параметрами подопций), CHARSET, TIMING-MARK и TLS — `telnets` и STARTTLS (опция 46), с клиентскими сертификатами (см. раздел «Telnet»). Клиентский сертификат берётся из хранилища Windows или из файла `.pfx`/`.p12` без пароля; файл с паролем нужно сначала импортировать в хранилище. CHARSET принимает кодировку терминала, если сервер предложил её, иначе отвечает `REJECTED`; сменив кодировку на панели, клиент сам предлагает серверу новую (CHARSET REQUEST), если тот уже согласовал какую-то, но по запросу сервера кодировку терминала не меняет. Опции AUTHENTICATION (37) и ENCRYPT (38) по-прежнему отклоняются: они требуют Kerberos/SRP и шифров DES/CAST, которые устарели и небезопасны, — их заменяет TLS (`telnets` или STARTTLS). Также отклоняются ENVIRON (36, старый вариант NEW-ENVIRON), COM-PORT-OPTION (44) и END-OF-RECORD (25).
- **Одиночные файлы — SCP или SFTP; файловая панель, редактор и каталоги — SCP, кроме Windows-хоста.** Передачи в очереди (**View → SCP Transfers**) могут идти по SFTP: настройка **Transfer protocol:** в **Settings** (по умолчанию SCP; SFTP берётся только там, где сервер его предоставляет, иначе автоматически используется SCP — так на OpenWrt без `openssh-sftp-server`). На Unix-хостах файловая панель, редактор и передача каталогов по-прежнему используют SSH-каналы и удалённые команды (`cp`, `mv`, `rm`, `mkdir`, `tar`), поэтому сервер, доступный только через подсистему SFTP, для них недостаточен. Исключение — Windows-хост: удалённых команд Unix у него нет, поэтому и список файлов, и файловая панель, и редактор, и передача каталогов работают там по SFTP (смену прав, `chmod +x` и распаковку архивов Windows-хост не поддерживает).
- **COM/TCP во вкладках:** профили COM/TCP из списка внутри главного окна можно открывать, но создавать TCP-профили и изменять профили COM/TCP можно только в окне выбора подключений (**New Raw TCP connection...**, значок редактирования), которое показывается при запуске и снова открывается командой **File → Open another session**. TCP-профиль можно удалить там же значком удаления, а для COM-профиля кнопка удаления скрыта. Изменения, сделанные на панели вкладки (скорость COM-порта, кодировка), действуют только в этом сеансе и не записываются в сохранённый профиль.
- **Режим отображения raw-терминала:** список `Text only`, `Hex only`, `Text and hex` в настройках подключения задаёт вид терминала: `Text only` — обычный текст, `Hex only` — только HEX-дамп, `Text and hex` — HEX-дамп с колонкой печатных ASCII-символов. Выбор сохраняется в профиле подключения. Панель `ASCII / HEX / Text + HEX` переключает вид сразу; для профиля, сохранённого в файле, новый режим записывается в этот профиль и сохраняется между сеансами. Для автоматически найденного COM-порта без сохранённого профиля переключение действует только в текущем сеансе — профиля, куда его записать, ещё нет.
- **Логи:** у COM/TCP есть непрерывная запись принимаемых данных (**Start log**), а `Save output to file` сохраняет снимок накопленного вывода. Запись вывода SSH-сеанса (**Log all terminal output to a file**) скрыта в обычном интерфейсе и недоступна из меню. Воспроизведение при этом доступно: **File → Replay log** показывается для SSH-вкладок и вкладок терминала устройства (COM/TCP/Telnet), а на панели терминала устройства есть кнопка **Replay**; оно только воспроизводит ранее сохранённый файл.
- **Протоколы передачи по последовательной линии:** XMODEM, XMODEM-1K, YMODEM, ZMODEM, Kermit и передача gzip + base64 и gzip + cat через оболочку есть только во вкладках устройства (COM, Raw TCP, Telnet). В SSH-вкладках этих пунктов нет: там файлы идут по SCP или SFTP.
- **Перетаскивание файла в терминал устройства:** файл (или несколько файлов), брошенный на вкладку устройства (COM, Raw TCP, Telnet), открывает окно «Send file to the device», где выбирается способ отправки: XMODEM, XMODEM-1K, YMODEM, ZMODEM, Kermit, gzip + base64, gzip + cat или «сырая» отправка без протокола. XMODEM, gzip + base64, gzip + cat и сырая отправка принимают один файл, YMODEM, ZMODEM и Kermit — несколько; папки пропускаются. Для gzip + base64 и gzip + cat следующее окно спросит путь на устройстве (файл уже подставлен). Приёмник на устройстве нужно запустить до перетаскивания: во время передачи терминал принадлежит протоколу (ZMODEM на приглашении оболочки запускает `rz` сам). Последний выбранный протокол запоминается до конца работы программы. Тот же код запускается и из меню кнопки передачи файлов.
- **Ширина символов:** две клетки занимают символы, которые Unicode 15.1 относит к широким и полноширинным (East Asian Wide и Fullwidth): иероглифы, кана, хангыль, полноширинные формы, эмодзи. Ни одной клетки не занимают символы, которым `wcwidth` даёт нулевую ширину: комбинирующие знаки, селекторы вариантов (U+FE0F после эмодзи), соединители (U+200D) и другие форматирующие символы; такой знак рисуется над буквой перед ним (если в Unicode есть готовая буква с этим знаком, например «é», рисуется она), а при копировании идёт сразу после неё, как пришёл. Знак в самом начале строки экрана, где буквы перед ним нет, не показывается. Так же и в строке ввода Smart Terminal и терминала устройства: курсор, Backspace и Delete проходят букву вместе со знаками после неё. Редкие узкие символы за пределами основной плоскости Unicode занимают две клетки вместо одной; поиск сравнивает буквы без знаков над ними. В байтовом режиме терминала устройства каждый символ занимает одну клетку: там устройство считает колонки байтами. При копировании, поиске и открытии ссылок широкий символ — один символ текста.
- **Байтовый режим:** он меняет только обработку строки ввода и имеет смысл лишь при кодировке UTF-8. В однобайтовых кодировках (Windows-1251, CP866 и т. п.) каждая буква и так занимает один байт, поэтому режим ничего не меняет. У SSH-вкладок он определяется при открытии вкладки (от этого зависит PTY) и на лету не переключается.
- **Масштабирование под DPI:** приложение объявляет Per-Monitor V2 в `app.manifest`. Окна, диалоги, терминалы, редактор, панель COM/TCP-терминала, их меню и всплывающие подсказки — WPF, и при переносе окна на монитор с другим масштабом WPF пересчитывает их сама; терминал и редактор сохраняют шрифт из настроек и показывают его в масштабе монитора. Элементов управления WinForms внутри окон больше нет. До Windows 10 версии 1607 система не сообщает DPI отдельного окна, и всё масштабируется по системному DPI.
- **Локальный репозиторий OpenWrt:** пункт меню появляется только для SSH-сеанса, хост которого опознан как OpenWrt, и работает, только если на устройстве разрешён TCP-forwarding, а выбранные папки содержат пакеты того типа, который использует устройство (`.ipk` для opkg, `.apk` для apk). Сервер слушает только `127.0.0.1` этого компьютера и доступен устройству лишь через обратный SSH-туннель.
- **Совместимость:** Smart Terminal, файловая панель и менеджер пакетов зависят от доступных удалённых команд и формата их вывода. Их наличие в интерфейсе не гарантирует поддержку любой shell, прошивки устройства или Linux-системы.
